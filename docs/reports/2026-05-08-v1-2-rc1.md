## Acceptance — met

The Q2 Y2 acceptance criterion was:

> "a 5 GB dataset uploaded twice (different runs) ends up with a single
> physical copy + two pointer rows."

Verified two ways:

1. **Unit-scale**: `TestDatasetDedup` uploads ~14 KiB of bytes twice under
   different names → CAS root has exactly 1 physical file; `datasets_v2`
   has 2 rows referencing the same `content_hash`.
2. **Live**: `smoke-demo` (id=2) and `smoke-demo-copy` (id=3) on
   https://lmf.gorev.space share `content_hash
   77f59d8296b7e9637c3387ece435af4bec42454dd921af97c7b7c7734d1515da`.

The 5 GiB scenario in the roadmap is qualitatively the same — limited only
by upload bandwidth. The design has no per-file size penalty: SHA-256 is
streamed during the upload write, the rename is a single inode op.

## Architectural decisions

- **Pure-Go CAS, no chunking.** DVC does Merkle-tree chunking for partial-file
  re-upload; we whole-file content-address. Simpler, hits the acceptance.
  Chunked CAS is a v2 candidate if a customer asks.
- **Soft-delete only.** A dataset version may share its content_hash with
  another version (mirrored from MLflow log_input, or two manual uploads of
  the same bytes). Hard-deleting the CAS file would break the others. The
  `DatasetHashStillReferenced` helper supports an offline GC sweep.
- **Mirror into v0.3 + datasets_v2.** Legacy `dataset_inputs` is preserved
  for byte-identical MLflow compat; `datasets_v2` is populated additionally.
  Drop v0.3 tables in v2.0 (per `docs/roadmap-y2.md`).
- **Body-limit middleware allowlist** instead of per-route middleware. Keeps
  the cap centralised; new large-upload routes opt in via `isLargeUploadPath`.

## Independent review

Spawned a fresh-eyes review agent on the v1.2 diff. **1 CRITICAL, 3 MAJOR,
11 MINOR (already-correct)**. All blocking items fixed before tag.

| Severity | Finding | Fix |
|---|---|---|
| **CRITICAL** | `mirrorIntoDatasetsV2` race: concurrent `MlflowClient.log_input` calls with identical `(workspace, name, digest)` computed the same `MAX(version)+1`, hit `UNIQUE(workspace_id, name, version)`, aborted the parent txn entirely | SAVEPOINT around mirror INSERT; on UNIQUE conflict, ROLLBACK TO SAVEPOINT and retry the existence-check (peer's row will be visible). 3-attempt cap. New `TestLogInputsConcurrentMirror` reproduces with 8 concurrent workers and asserts exactly 1 mirrored row. |
| MAJOR | `ParseMultipartForm` permitted up to 32 MiB of `meta` JSON in memory; `json.Unmarshal` then doubles that transiently | Hard 64 KiB cap on `meta` before unmarshal |
| MAJOR | `maxDepth=256` in `GetDatasetLineage` was a node cap that could be blown past inside a wide frontier (single level with >256 nodes returned thousands) | Restructured BFS with `break ancLoop`/`break descLoop` labels; renamed to `maxLineageNodes` |
| MAJOR | `sanitizeFilename` only stripped `"`/`\`/CR/LF/NUL — left `;`, U+202E (RTL override), other non-ASCII through; could mislead clients on download | Strict ASCII allowlist (printable 0x20–0x7E minus shell/path metacharacters). 14-case `TestSanitizeFilename` including bidi-override + path traversal + header injection. |

The reviewer also walked through and confirmed safe: CAS atomic-rename
race semantics, `pathFor` traversal defense, `isLargeUploadPath` route
suffix correctness, `ListDatasets` lifecycle filter, indirect-cycle
prevention contract, UI XSS coverage, all 7 stub-store updates, empty-
backfill no-op.
