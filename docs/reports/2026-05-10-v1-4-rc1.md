# v1.4.0-rc1 — Lineage DAG (time-travel deferred)

Release date: 2026-05-10
Roadmap target: docs/roadmap-y2.md → Q4 Y2

## Headline

> A run with N ancestors and M descendants renders correctly; clicking on a node opens the run page.

The full DAG view is at `#/experiments/{expID}/runs/{runID}/lineage`.
Toolbar exposes direction (upstream / downstream / both) and depth (1–8).

## Scope cut

The Q4 Y2 roadmap entry combined two streams:

- **Lineage DAG** — directional walks, dataset edges, SVG view. **Shipped in this rc.**
- **Time-travel** — append-only event log + snapshot table + `?as_of=<ts>` queries. **Deferred to v1.5.** This is a write-path-wide refactor: every metric/param/tag write needs a mirror to an event log, and replay logic for time-qualified reads. It is a session-scale undertaking, not the right thing to bundle with a UI feature.

## What shipped

### Backend

- Extended `Store.GetRunLineageWithOptions(ctx, runID, LineageOptions)`:
  `Direction = upstream | downstream | both`, `DescendantDepth ∈ [1, 8]`,
  `MaxNodesPerLevel ∈ [1, 200]`. Existing `GetRunLineage` delegates with
  depth=1 for backward compatibility.
- `walkAncestors` (parent-chain) and `walkDescendants` (BFS, one query per
  level via `WHERE parent_run_id IN (...)`) — both workspace-scoped via
  `JOIN experiments e ON e.id = r.experiment_id WHERE e.workspace_id = ?`.
- `runDatasetEdges`: LEFT JOIN `dataset_inputs` ⨝ `datasets_v2` on
  `(name, content_hash, workspace_id)`. Workspace filter prevents cross-tenant
  row explosion and version leakage. Falls back to `Version=0/DatasetID=0`
  for legacy v0.3 inputs without a v1.2 mirror.
- New response shape: `RunLineage.Datasets []DatasetEdge` and
  `RunLineage.Truncated bool`. Slices initialized to empty (not nil) so
  the JSON wire shape is `[]`, not `null`.

### HTTP

`GET /api/v1/runs/{runID}/lineage` accepts `?direction`, `?depth`,
`?fanout`. Out-of-range / non-numeric values return 400 with
`INVALID_PARAMETER_VALUE`.

### UI

- New route `#/experiments/{expID}/runs/{runID}/lineage` with SVG
  layered DAG renderer (ancestors top → current → descendants bottom),
  dataset strip below the current run linked through to the v1.2
  dataset detail at the specific version.
- Inline lineage card on the run detail page now shows dataset chips and a
  "View full DAG" link.
- Direction + depth controls re-route via query string.
- Click + Enter/Space keyboard navigation on every node.

## Operator notes

- Workspace isolation: lineage walks are now strictly contained within the
  seed run's workspace. A `mlflow.parentRunId` tag pointing into another
  workspace is silently ignored (returns no ancestor) — this is intentional.
- `GET /api/v1/runs/{id}/lineage` is unchanged in its default response;
  new fields (`datasets`, `truncated`) are additive. Old SDK clients that
  ignore unknown fields keep working.
