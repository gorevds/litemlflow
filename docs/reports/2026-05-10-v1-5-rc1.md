# v1.5.0-rc1 — Time-travel (read-side, runs + tags)

Release date: 2026-05-10
Roadmap target: docs/roadmap-y2.md → Q4 Y2 (the time-travel half deferred from v1.4)

## Headline

> "Show me what this run looked like at unix-ms T."
>
> `GET /api/2.0/mlflow/runs/get?run_id=<id>&as_of=<unix_ms>` returns the
> run state, tags, and the latest metric per key as they were at T.

## Scope cut for rc1

This rc ships **read-side** time-travel for the run + tag surface:
- `?as_of=<unix_ms>` on `runs/get` and `metrics/get-history`.
- Append-only event log mirrors run UPDATE / lifecycle / parent_run_id /
  tag set / tag delete.
- Replay strategy: read current state, undo events newer than T in reverse.

Out of scope for v1.5-rc1, planned for v1.5 stable / v1.6:
- `runs/search?as_of=` (the search loop calls `collectRunData(asOf=0)` for now).
- UI date-picker on the run detail page.
- Experiment-level events (rename, lifecycle).
- Param time-travel (params are insert-only with no native timestamp; would need event-log extension).
- Events-table TTL / janitor sweep.

## What shipped

### Schema
- Migration `013_events.sql`: `events(id, ts_ms, kind, entity_type, entity_id, payload)` with composite index `(entity_type, entity_id, ts_ms, id)` and a secondary `(ts_ms)` for system-wide audit queries. Kinds in v1.5: `run_update`, `run_lifecycle`, `run_parent`, `tag_set`, `tag_delete`. Entity type is always `'run'` for now — reserved for `'experiment'` in a future migration.

### Store
- `Store.GetRunAsOf(ctx, runID, asOfMs) → (*Run, []KV, error)` and the workspace-scoped `GetRunAsOfInWorkspace`. Returns `ErrNotFound` when `run.StartTime > asOfMs`.
- `Store.GetLatestMetricsAsOf(ctx, runID, asOfMs)` reduces metric history per key in SQL — picks the latest observation `<= asOfMs`.
- All run-mutating methods now mirror to `events`: `UpdateRun`, `SetRunLifecycle`, `SetTag`, `SetTags`, `DeleteTag`, `setParentRunID`, `syncParentRunIDFromTag`, `ArchiveStaleRuns`. Each captures `before` (pre-state) for replay undo.
- New helpers: `captureRunBefore`, `readTagValue`, `tryWriteRunEvent` (logs on event-write failure via `slog.Warn` instead of silently dropping).

### HTTP
- `GET /api/2.0/mlflow/runs/get?as_of=<ms>` reconstructs run + tags via `GetRunAsOfInWorkspace`, surfaces the metric reduction, returns 404 if the run did not exist at T.
- `GET /api/2.0/mlflow/metrics/get-history?as_of=<ms>` filters to entries with `timestamp <= as_of` (free — append-only with native ts).
- `parseAsOf` rejects 0/negative/non-integer values with 400.

## Independent review (subagent: general-purpose)

13 findings. Three were **critical** and required fixes before tagging:

| ID | Severity | Issue | Status |
|----|----------|-------|--------|
| C1 | critical | `runs/get?as_of` filtered the latest-per-key list — silently dropped metric keys whose latest point post-dated as_of, even when an earlier observation predated it | **fixed** — new `GetLatestMetricsAsOf` does the per-key reduction in SQL. Test: `TestEventsMetricsAsOfReducesPerKey`. |
| C2 | critical | `setParentRunID` and `ArchiveStaleRuns` inserted tags via raw SQL, bypassing SetTag and producing no `tag_set` event → corrupt replay for any run that auto-archived or had a parentRunId set | **fixed** — both paths now capture before-state and call `tryWriteRunEvent`. |
| H3 | high | `GetRunAsOf` had no workspace gate — viewer in ws-A could reconstruct historical state of a ws-B run by guessing run_id (same vector as v1.4 lineage; the new read path forgot the lesson) | **fixed** — new `GetRunAsOfInWorkspace` reuses the v1.4 `getRunInWorkspace` helper, returns ErrNotFound for cross-workspace lookups. HTTP handler routes through the workspace-scoped variant. Test: `TestEventsRunAsOfWorkspaceIsolation`. |
| H1 | high | `SetTags` (bulk) wrote zero events → MLflow client's start_run system-tag bundle had no audit trail | **fixed** — bulk path captures before-values per key, writes events after commit. |
| H2 | high | Race on capture-before/UPDATE/event sequence | **partial** — events still written outside the same txn (the comment in `sqlite_events.go` admits this), but the auto-archive path now writes events post-commit so a rollback doesn't leave orphan rows. Full single-txn fix deferred to v1.5 stable. |
| M2 | medium | Errors from `writeRunEvent` silently dropped | **fixed** — `tryWriteRunEvent` wrapper logs via `slog.Warn` on failure. |

Deferred to v1.5 stable / v1.6:
- M1 (future as_of validation), M3 (event-read cap), M4 (events TTL), M5 (perf), M6 (redundant captured fields), L1–L5 (cosmetic).

## Operator notes

- The `events` table grows monotonically. With `metrics` already excluded, growth is dominated by `tag_set` (most frequent in MLflow workflows). Plan a periodic sweep `DELETE FROM events WHERE ts_ms < ?` for any retention window beyond a few weeks; v1.5 stable will ship a built-in janitor.
- `?as_of` returns the run state and tags as of T, plus the latest metric per key with `timestamp <= T`. Params return current values regardless of as_of (no native timestamp; planned for v1.6).
- Cross-workspace isolation: `runs/get?as_of=` returns 404 for run_ids outside the caller's workspace, even if the run exists.
